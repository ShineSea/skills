# 渲染 QA、修改范围与完成标准

所有完整网页 PPT 任务必须读取本文件。真实浏览器渲染是视觉判断依据；DOM 检查、构建成功和自动检查都不能取代视觉检查。

## QA 强度与任务阶段

制作过程中可用受影响页面的快速预览迭代。最终交付前执行与影响范围匹配的完整验收：

- 新建演示：渲染并检查全部页面，生成完整 contact sheet。
- 局部修改：检查目标页面；若影响前后节奏，再检查相邻页。
- 共享组件修改：找出全部使用位置，渲染这些页面并检查跨页一致性。
- 全局 Design System 修改：重新渲染全部页面并生成完整 contact sheet。
- 增删页面、调整顺序或改变故事线：重建受影响 slide map；若全局节奏改变，重新渲染整套演示。

影响范围不确定时，按可能受影响的最大合理范围检查。

## 修改已有网页 PPT

修改前同时检查源文件和真实渲染结果，建立基线：Reveal 初始化、页面层级、数量、顺序、fragment、转场、资源、字体、共享样式、局部覆盖、组件及当前视觉异常。

识别现有设计系统并区分：

- **稳定规则**：跨页一致且有效，应继续遵循。
- **有意例外**：服务于封面、章节、全幅视觉或关键页面，应保留其目的。
- **真实缺陷**：没有明确目的且造成不一致或可用性问题，可在范围允许时修正。

不要用本 Skill 的偏好覆盖成熟系统。只重构完成用户目标所需的范围；共享规则在共享实现中修改。已有问题若影响本次修改或最终验证，应处理；无关问题可以记录，但不要擅自扩大范围。

## 浏览器渲染

以 1920 × 1080 目标视口渲染，截图前等待字体、图片、图表和异步布局完成。

- 按页面顺序使用可预测文件名保存截图。
- 每页至少捕获预期的最终 fragment 状态。
- 每个动效页至少捕获一个有意义的中间状态和最终状态；多个独立阶段按需增加截图。
- 连续播放所有相关动效页，验证进入、推进、回退、重新进入、快速翻页和深链。
- 不能通过关闭动画后的截图代替真实动效行为验证。

## Contact sheet

用相关页面截图按顺序生成带页码或文件名的 contact sheet。检查叙事节奏、密度变化、色彩分布、构图重复、边距和 chrome 一致性、风格跳变、章节过渡、缺页、重复页和顺序错误。

## 内容完整性

核对“源文档 → 页面规划 → 页面”或“大纲 → 页面”：

- 必需章节、名称、日期、数字、单位、标签和限制准确。
- 精简与重写没有改变原意，重要信息没有因难排版而消失。
- 图注、图例、视觉内容和来源相互匹配。
- fragment 隐藏内容会在最终状态完整出现。
- 页面顺序支持预期叙事；修改任务没有误改无关内容。
- 没有生成器插入的 `…`、CSS 省略号或固定字数截断造成语义残缺。

## Slide-level QA

逐页查看完整尺寸结果，重点检查：

- 视觉焦点、阅读顺序、文字层级和投影距离下的可读性。
- 换行、孤行、截断、裁切、过密文本、边缘拥挤和意外相切。
- 间距、对齐、平衡、光学居中、图片比例与主体位置。
- 图表标签、图例、单位、来源和对比度。
- Logo、页码、页脚、来源行以及图标、箭头、线条和颜色的语义。
- 初始、中间和最终动效状态；前进、回退、重播和深链状态。
- `prefers-reduced-motion` 下内容完整、可读，没有错误隐藏或半透明元素。
- 与用户目标、品牌和参考方向一致。

特别检查首页、章节转换页、结尾页、模板外页面和高密度页面。

## 自动布局与运行检查

对所有相关页面及动效状态检查：

- 页面边界、意外 overflow、容器裁切和非预期重叠。
- 图片、图表或嵌入资源缺失、尺寸为零或比例异常。
- 请求失败、控制台错误、重复 ID 和无效 Reveal 页面结构。
- 页面数量与规划一致，必要内容没有缺失。
- `data-motion="required"` 页面存在实际 fragment 或动画挂钩。
- 深链、前进、后退、重新进入和减少动态效果模式状态一致。

可用元素边界框、文本节点边界、计算样式、滚动尺寸和资源加载状态辅助判断，但要排除有意出血、阴影和变换造成的误报。自动检查不能代替视觉检查。

## 修复循环

发现问题后定位到 HTML、CSS、JavaScript、内容或素材，修改源文件，重新渲染全部受影响页面并重复相关检查。共享 token、字体、素材、组件或 chrome 改变时扩大回归范围；影响整套节奏或顺序时重新生成完整 contact sheet。重复直到没有实质问题。

## 完成标准

只有以下条件满足时才交付完整网页 PPT：

- 从源文档开始时，页面级 Markdown 规划稿已落盘并通过内容充分性闸门。
- 最终静态构建可以通过 HTTP 独立运行，启动方式可复现，不依赖开发环境或未声明的网络资源。
- 计划页面、必要内容、设计系统和用户要求均已落实。
- 导航、深链、资源、fragment、元素级动效、重播和减少动态效果模式按范围验证。
- 所有相关页面以及必要的动效中间与最终状态已渲染检查。
- 新建演示已生成完整 contact sheet；修改任务完成与影响范围匹配的回归。
- 内容、视觉、运行和自动布局检查通过，实质问题已在源文件中修复并复验。

如果环境缺少浏览器、截图、HTTP 或其他验证能力，先尝试项目已有工具或安全可用替代方案；仍无法完成时，交付中明确列出未验证项和原因，不能声称全部 QA 已通过。
