# 叙事、视觉系统与动效

创建完整网页 PPT、视觉重构或新增页面时必须读取本文件。

## 整套演示结构

先建立 slide map，再写代码。每页至少明确沟通目的、观众应记住的结论、必要内容和证据、主次层级、内容关系、视觉结构理由、素材需求及动效判定。

从整套演示检查开场、展开、收束、页面过渡、节奏、密度、视觉变化和内容覆盖。页数由信息量、演讲时长和用户限制决定，不预设“三章十页、每页三点”。

参考图默认提供视觉语言：构图张力、色彩、字级、光感、留白、线条、形状、图片和图表风格。除非用户明确要求复刻，不把参考图的具体模块位置机械搬到所有页面。

## 逐页设计决策

每页建立一个清晰焦点和阅读顺序，用比例、位置、对比和空间表达层级；聚合相关信息，分隔无关信息。图形、线条、箭头、图标和颜色应表达分类、方向、状态或强调，而不是装饰。

用一个判据检查页面：去掉标题后，构图是否仍能表达本页独有的内容关系？如果只是把另一页的卡片换词，应重新设计。

允许主张页、编辑式分栏、流程、对比、时间线、系统图、数据故事、案例、带标注图片或全幅视觉使用不同结构，但必须共享一致的视觉身份。设计应保证投影距离下的可读性，并避免过密段落、无意义卡片网格和纯装饰图表。

## 首页与结尾页

首页必须建立第一视觉重点、核心命题和演示身份，不能只是标题容器。应体现用户主题和参考方向，但不要堆叠摘要、目录和多组次要信息。

最后一页必须完成内容收束并自然表达感谢。根据任务可包含结论、行动方向、联系方式或一句与主线相关的结束语，但不能只有孤立的“谢谢观看”，也不能新增材料没有支持的承诺。

## Design System

先完成页面设计，再从真实重复模式中提取设计系统和组件：

- 1920 × 1080、16:9 画布、安全区、网格、边距和共同对齐锚点；
- 展示字、标题、正文、图注、数据标签和来源文字层级；
- 背景、表面、正文、强调、状态和数据系列的颜色语义；
- 间距、圆角、描边、阴影、连接线、箭头和图标的形状语言；
- 图片裁切、遮罩、图注，以及图表轴、单位、标签、图例和来源；
- Logo、页码、章节标识、页脚、来源行等 global chrome。

一致性不等于相同布局。独特页面可以保持独特，不为抽象建立比演示本身更复杂的组件系统。Chrome 信息避免重复占位，页码、章节号和业务步骤号应明确区分。

## 动效判定

逐页把动效标记为**必需**、**可选**或**静态**，并记录内容理由。流程、时间线、因果链、层级展开、关系网络、数据流、图表增长、地图路径、步骤操作或前后状态变化通常需要元素级动效；若保持静态，说明运动为何不会改善理解。

封面、单一主张、简短结论、法律声明或一眼可读的构图可以静态。不要为了动效数量添加无意义的漂移、缩放或淡入。

## 动效语法

- 流程按步骤推进；关系图先建立核心对象，再建立连接。
- 图表先呈现坐标、基线或语境，再展示数据与结论。
- 时间线按事件顺序进入；前后状态应让变化对象明确可比。
- 同一时刻只让当前叙事焦点运动，其他必要上下文可以预显。
- 动效不暗示未经证实的数据更新、交互或业务状态。
- 最终文字、数值、位置和尺寸必须与静态最终版一致。

页面 transition 不算内容动效。离散步骤适合 Reveal fragment；连续路径、连线、进度和图表绘制可用 CSS、Web Animations API 或 SVG 动画。具体实现与验收遵循 `implementation-delivery.md` 和 `qa-and-revision.md`。
