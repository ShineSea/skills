# 网页实现、构建与独立交付

创建或修改完整网页 PPT 时必须读取本文件。最终产物是已经构建完成、可由普通静态 HTTP 服务访问的网页演示，不要求运行端安装 Node.js、npm、Vite、Webpack 或 Reveal.js 开发环境。

## 实现要求

可以使用 Reveal.js 和必要的构建工具开发，但最终交付必须包含浏览器直接需要的 HTML、CSS、JavaScript、字体、图片和其他资源。默认使用水平页面，除非用户明确要求垂直嵌套。

Reveal.js 目标配置：

```js
Reveal.initialize({
  width: 1920,
  height: 1080,
  margin: 0,
  minScale: 0.1,
  maxScale: 2,
  hash: true,
  center: false
});
```

实现应做到：

- 包含计划中的全部页面、内容与必要资源。
- 使用语义清晰的 HTML、可维护的 CSS 和完成效果所需的最少 JavaScript。
- 用 CSS 自定义属性表达真实重复的设计 token，并限制演示专用样式的作用范围。
- 保持合理 DOM 顺序和文本可访问性；信息性图片提供有意义的替代文本，装饰图片不干扰阅读顺序。
- 稳定布局可用时避免脆弱的绝对定位；艺术化构图需要时可以有意使用绝对定位。
- 字体与资源可靠加载，并为失败状态提供清楚的替代显示。
- 不保留占位图、lorem ipsum、空容器、虚构数据或未完成注释。

## 动效实现

- 离散步骤优先使用 `.fragment` 和明确顺序；连续路径、连线、进度或图表绘制可使用 CSS、Web Animations API 或 SVG stroke 动画。
- 触发绑定 Reveal 的 `ready`、`slidechanged`、`fragmentshown`、`fragmenthidden` 等可靠事件，不依赖固定延时猜测页面是否出现。
- 用清晰的类或数据属性记录状态，例如 `data-motion="required"`、`data-motion-step`，便于检查声明与实现一致。
- 返回页面时可以正确重播；深链打开和快速连续翻页不会让元素卡在半完成状态。
- 支持 `prefers-reduced-motion`，启用时直接显示完整、可读的最终内容。
- 不用视频或 GIF 代替本应由页面结构表达的流程动效，除非素材本身就是用户要求展示的证据。

只要存在标记为“必需”的页面，最终实现就必须包含对应的 fragment 或元素级动画，不能只有全局 transition。

## 静态构建产物

推荐将最终产物放入清晰的发布目录，例如：

```text
dist/
├── index.html
├── assets/
│   ├── styles.css
│   ├── presentation.js
│   ├── images/
│   └── fonts/
└── vendor/
    └── reveal.js/
```

具体结构可以调整，但必须满足：

- 所有运行时依赖已构建或复制到发布目录，不引用开发机绝对路径、临时目录或源代码目录。
- 默认不依赖在线 CDN、在线字体或其他网络资源；若用户明确接受联网依赖，应说明它们及离线影响。
- 不需要在运行端执行 `npm install`、构建命令或开发服务器。
- 使用相对 URL 或适合部署路径的 URL，直接访问首页、嵌套路径和带 hash 页面时资源均能加载。
- 开发源文件与最终发布目录职责清晰；不要把庞大的依赖缓存或 `node_modules` 当作交付物。

如果用户明确需要单文件交付，可以内联必要 CSS、JavaScript 和小型资源，但仍需权衡文件体积、字体、图片和离线可用性。

## HTTP 运行方式

提供最简单、可复现的静态 HTTP 启动方式和访问地址。例如使用环境已有的静态服务器，而不是要求特定前端工具链。必须在最终发布目录上实际验证，不能只验证开发服务器。

至少检查：

- 首页和跨页导航正常；
- 直接访问带 hash 的页面正常；
- CSS、JavaScript、字体、图片和 vendor 资源无失败请求；
- 浏览器控制台没有影响演示的错误；
- 断开外网后仍可使用，除非用户明确接受联网依赖。

不要用 `file://` 或只看截图来证明最终项目可运行。
