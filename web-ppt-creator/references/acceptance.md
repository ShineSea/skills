# 最终验收：步骤与标准

所有完整网页 PPT 任务必须按本文件验收。真实浏览器渲染是视觉判断依据；构建成功、DOM 正常或自动检查通过都不能代替真实视觉检查。

## 验收范围

最终交付前执行与任务影响范围匹配的完整验收：

- **新建演示**：全部页面执行完整验收流程，生成完整 contact sheet。
- **局部修改**：检查目标页面；若影响前后节奏，再检查相邻页。
- **共享组件修改**：找出全部使用位置，渲染这些页面并检查跨页一致性。
- **全局 Design System 修改**：重新渲染全部页面并生成完整 contact sheet。
- **增删页面、调整顺序或改变故事线**：重新渲染受影响页面；全局节奏改变时重新渲染整套演示并生成完整 contact sheet。

影响范围不确定时，按可能受影响的最大合理范围验收。制作过程中可用受影响页面的快速预览迭代，但不能以预览代替最终验收。

## 验收步骤

### 第 1 步：浏览器渲染与截图

在真实浏览器中以 1920 × 1080 目标视口，通过最终发布目录的 HTTP 地址渲染演示文稿。截图前等待字体、图片、图表和异步布局完成。

- 按页面顺序使用可预测文件名保存截图。
- 每页至少捕获预期的最终 fragment 状态。
- 每个动效页至少捕获一个有意义的中间状态和最终状态；包含多个独立叙事阶段时按阶段增加截图。
- 确认截图数量与计划页面数量一致。
- 除静态截图外，至少连续播放一次所有动效页，验证进入、逐步推进、回退、重新进入、快速翻页和深链访问；不能通过关闭动画后的截图代替真实动效行为验证。

不要用 DOM 检查或 `file://` 页面代替实际渲染。

### 第 2 步：生成 contact sheet

用所有相关页面截图按演示顺序生成可读的 contact sheet，并包含页码或文件名，便于定位源页面。

### 第 3 步：内容完整性核对

核对“源文档 → 规划稿 → 最终页面”或“大纲 → 最终页面”。该映射用于确认重要内容没有丢失，不要求规划稿页面与最终页面严格一一对应。检查：

- 从源文档开始时，规划稿已落盘并通过内容充分性闸门。
- 必需章节、名称、日期、数字、单位、标签和限制准确；重要结论有对应证据或机制，编辑归纳未被误写为源文档事实。
- 输入输出、依赖、异常、权限、性能、安全和验收边界在相关页面得到保留。
- 精简与重写没有改变原意；重要信息没有因难排版而消失；没有程序化截断遗漏后续内容。
- 图注、图例、视觉内容和来源相互匹配。
- fragment 隐藏内容会在最终状态完整出现。
- 页面顺序支持预期叙事；修改任务没有误改用户未要求改变的内容。
- 没有生成器插入的 `…`、CSS 省略号或固定字数截断造成的语义残缺。

### 第 4 步：逐页检查（slide-level）

逐页查看完整尺寸渲染图，检查：

- 视觉焦点、阅读顺序、文字层级和投影距离下的可读性。
- 换行、孤行、截断、裁切、省略号、半句、过密段落、边缘拥挤和意外相切。
- 间距、对齐、平衡、光学居中、图片质量、比例与主体位置。
- 图表和图解的标签、图例、单位、来源和对比度。
- Logo、页码、页脚、来源行位置；图标、箭头、线条和颜色有明确语义。
- 动效初始状态不会错误隐藏标题或必要上下文；中间状态有清晰焦点，进入顺序与讲述顺序一致。
- 前进、后退、重新进入和深链时，fragment、连线、图表或步骤动画正确恢复和重播。
- `prefers-reduced-motion` 下直接显示完整最终状态，没有不可读的半透明元素。
- 与用户目标、品牌和参考方向一致。

页面只有在能清楚表达预期内容、具有适合该内容的构图，且没有可见渲染问题时才通过。特别检查首页、章节转换页、结尾页、模板外页面和高密度页面；不能只看缩略图或只抽查几页。

### 第 5 步：整套检查（deck-level）

通过 contact sheet 和连续播放检查：

- 叙事流、章节结构和相邻页面的视觉节奏。
- 字体、颜色、间距、图像和 chrome 的统一性。
- 节奏与密度变化、色彩分布是否均衡；安静页与密集页是否有意交替。
- 构图是否过度重复；需要连续性的地方是否有适当重复。
- 边距或 chrome 是否不一致；是否出现突然的风格跳变；章节过渡是否清晰。
- 关键页面是否得到清晰强调；开场是否有吸引力，结尾是否完整。
- 页面是否缺失、重复或顺序错误；转场和动效是否一致。

一致性不等于相同布局：整套演示应具有共同身份，同时允许每个观点使用最适合它的构图。

### 第 6 步：自动布局与运行检查

字体和资源加载完成后，在 1920 × 1080 目标视口对所有相关页面（及动效各状态）运行浏览器检查：

- 元素是否越出页面边界；是否出现意外的水平或垂直 overflow；文本或媒体是否被容器裁切；可见元素之间是否发生非预期重叠。
- 图片、图表或嵌入资源是否缺失、尺寸为零或比例异常；是否有资源请求失败或控制台错误。
- 是否有影响 Reveal.js 的重复 ID 或无效页面结构；页面数量是否与计划一致。
- 标记为 `data-motion="required"` 的页面是否存在实际的 fragment 或动画挂钩；若整套演示只有页面 transition，直接判定动效检查失败。
- 深链打开、前进、后退和重新进入后动效状态一致；减少动态效果模式显示完整最终内容。
- HTTP 运行验证：首页、跨页导航、hash 深链、资源加载正常；断开外网后仍可使用（除非用户明确接受联网依赖）。

可使用元素边界框、文本节点边界、计算样式、滚动尺寸和资源加载状态辅助判断；排除有意重叠、阴影、变换装饰和出血元素带来的误报。自动检查不能代替视觉检查。

### 第 7 步：修复循环

发现问题后：

1. 定位负责该问题的 HTML、CSS、JavaScript、素材或内容决策，在源文件中修复。
2. 重新渲染所有受影响页面并查看完整尺寸结果，重新执行相关自动检查。
3. 共享 token、全局样式、组件、字体、素材或 chrome 改变时，扩大回归范围重新渲染全部受影响页面。
4. 变化影响整套节奏、一致性或页面顺序时，重新生成并检查完整 contact sheet。
5. 重复以上过程，直到没有实质问题。

不要只通过阅读代码判断问题已经解决。

## 验收标准

### 新建演示的完成标准

只有以下条件全部满足时才完成：

- 若从源文档开始，已生成并核查包含事实依据和逐页结构的独立 Markdown 规划稿，且通过内容充分性闸门。
- 网页 PPT 能通过 HTTP 地址以 1920 × 1080、16:9 正常运行；启动方式可复现，导航、深链、资源和动效已验证。
- 规划的全部页面已经实现，必要内容完整、准确。
- 用户风格方向和参考得到可识别的体现；每页布局符合其沟通目的。
- Design System 在整套演示中保持一致；可复用组件来自真实重复模式。
- 所有标记为必需的页面已实现与内容关系对应的元素级动效；每个动效页的中间与最终状态已渲染检查，进入、回退、重播、深链与减少动态效果模式均已验证。
- 没有因固定字数截断产生的省略号或语义残缺。
- 全部页面已渲染并检查；完整 contact sheet 已生成并检查。
- 内容完整性、逐页、整套和自动布局检查全部通过；所有实质问题已在源文件中修复并通过重新渲染验证。

### 修改任务的完成标准

只有以下条件全部满足时才完成：

- 用户要求的修改已经落实到源文件，且通过 HTTP 地址验证受影响的页面和功能。
- 现有 Design System 已被识别并按任务要求保留或更新；修改没有意外破坏未涉及的内容和页面。
- 所有受影响页面已重新渲染并检查；验收范围与修改影响范围相匹配。
- 共享或全局修改已完成跨页回归检查；需要时已重新生成并检查完整 contact sheet。
- 内容、视觉和自动布局检查通过；所有实质问题已通过重新渲染验证。

### 验证能力受限时

如果环境缺少浏览器、截图、HTTP 或其他验证能力，先尝试项目已有工具或安全可用替代方案；仍无法完成时，交付中明确列出未验证项及原因，不能声称全部验收已通过。
